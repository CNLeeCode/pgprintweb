# 自动更新方案文档（方案 B：后端接口直返下载地址）

## 一、方案概览

放弃 electron-updater + latest.yml + 独立更新服务器整套机制，改用**后端接口直返版本号 + 下载地址**，主进程用 Node https 模块下载 nsis 安装包并 shell 静默安装。

### 对比原方案（electron-updater）

| 维度 | electron-updater | 方案 B |
|------|------------------|--------|
| 独立更新服务器 | 必须 | 不需要 |
| latest.yml + sha512 维护 | 必须每次发版手算 | 不需要 |
| 下载地址来源 | publish.url 配置 | 后端接口返回 |
| 发版流程 | 改 latest.yml + 传 exe + .blockmap | exe 丢静态目录 + 改接口返回 |

### 核心优势

- **发版极简**：无需维护 latest.yml，无需手算 sha512
- **下载地址可变**：前期用 IP、后期换域名，后端接口返回即可
- **复用现有后端**：不搭独立更新服务器

## 二、后端接口规范

### 接口地址

```
GET {域名}/index.php/Home/<接口前缀名>/getAppUpdateInfo
```

- 域名前期 IP、后期域名，由前端 `.env` 的 `VITE_UPDATE_CHECK_URL` 配置
- 与现有 `getLastAppVersionData` 同目录同控制器，新增一个 action
- 无需鉴权参数（与 `getLastAppVersionData` 一致公开）

### 请求参数

无

### 返回值结构

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "version": "1.0.72",
    "download_url": "http://<生产域名>/download/pgprint-setup-1.0.72.exe",
    "update_msg": "1. 修复切换门店后订单不显示问题\n2. 优化打印队列稳定性",
    "force_update": 0
  }
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| code | number | 是 | 200 成功，其他失败 |
| msg | string | 是 | 状态描述 |
| data.version | string | 是 | 最新版本号，格式 `x.y.z` |
| data.download_url | string | 是 | nsis `.exe` 完整下载地址，Win7 需 TLS1.2 |
| data.update_msg | string | 否 | 更新说明，弹窗展示 |
| data.force_update | number | 否 | 0=非强制（默认），1=强制更新 |

### 后端发版流程

1. 配置 `electron-vite build && electron-builder --win` 打包出 `pgprinter Setup 1.0.2.exe`
2. 把 exe 文件上传到静态目录（如 `http://<生产域名>/download/`）
3. 修改 `getAppUpdateInfo` 接口返回的 `version` + `download_url`，**完事**

## 三、升级流程

```
应用启动
  ↓
调 getAppUpdateInfo 接口
  ↓
版本对比（线上版本 > 本地版本？）
  ├─ 否 → 直接进登录页
  └─ 是
       ↓
      后台静默下载 exe 到临时目录（不打扰用户）
       ↓
      下载完成 → 广播 update:downloaded 事件
       ↓
      UI 弹"新版本已就绪" + "立即重启升级"按钮
       ↓
      用户点确认 → shell 启动 installer.exe /S --updated
       ↓
      当前进程退出 → nsis 静默覆盖安装 → 自启新版本
```

## 四、前端配置项

`src/main/config.ts`：

```typescript
// 更新检查接口地址（前期 IP，后期域名，改 .env 一行）
export const UPDATE_CHECK_URL =
  process.env.VITE_UPDATE_CHECK_URL || `${API_BASE_URL}getAppUpdateInfo`

// 自动下载（检测到新版本立即后台下载）
export const AUTO_DOWNLOAD = process.env.VITE_AUTO_DOWNLOAD !== 'false'

// 自动安装（下载完成直接静默安装重启，默认 false 等用户确认）
export const AUTO_INSTALL = process.env.VITE_AUTO_INSTALL === 'true'
```

`.env` 示例：

```bash
# 前期 IP
VITE_UPDATE_CHECK_URL=http://192.168.1.100/index.php/Home/<接口前缀名>/getAppUpdateInfo

# 后期换域名只改这一行
VITE_UPDATE_CHECK_URL=http://<生产域名>/index.php/Home/<接口前缀名>/getAppUpdateInfo
```

## 五、nsis 安装配置

`electron-builder.yml`：

```yaml
nsis:
  oneClick: true              # 一键安装，不问目录
  perMachine: true            # 装到 Program Files
  allowToChangeInstallationDirectory: false
  createDesktopShortcut: true
  createStartMenuShortcut: true
  runAfterFinish: true        # 装完自启
# 不配置 publish 段（不用 electron-updater）
```

**首次安装体验**：门店人员拿到 exe → 双击 → 几秒后桌面出现图标并自动打开应用，全程 0 决策。

**升级安装体验**：`installer.exe /S --updated` 静默覆盖安装，无任何对话框，装完自启新版本。

## 六、下载实现要点（UpgradeService.ts）

1. **Node https 模块**：不引第三方依赖，Win7 SP1+KB2533623 支持 TLS1.2
2. **302 重定向**：手动跟随，最多 5 次跳转防死循环（对象存储短链兼容）
3. **断点续传**：记录已下载字节数，Range 请求续传
4. **进度节流**：200ms 广播一次，避免频繁 setState 拖慢 UI
5. **临时目录**：`app.getPath('temp')`，Win7 友好
6. **失败清理**：下载失败删除半成品文件，下次重启重新下载

## 七、Win7 兼容性

- Node https 模块在 Win7 SP1+KB2533623 上支持 TLS1.2
- nsis `/S --updated` 静默安装无对话框
- 临时目录用系统 temp，Win7 路径 `%LOCALAPPDATA%\Temp`
- 安装包文件名带版本号，避免多版本混淆
