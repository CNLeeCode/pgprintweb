# 页面功能流程文档

> PG到家小票打印系统 Electron 版 —— 各页面功能说明、操作流程、状态流转。本文档供新同事快速了解产品交互。

## 一、整体导航

```
SplashView（启动检查）
   ├── 有新版本 → 下载更新 → 安装重启
   ├── 正常 → 自动跳转 Login/Home
   └── 异常 → 重试 / 继续旧版本
        ↓
LoginView（门店登录）—— 输入门店号
        ↓
HomeView（主页）—— 设备选择/平台选择/订单网格/设置
```

- 首次启动：Splash → Login → Home
- 已有门店号：Splash → Home（自动跳过登录）
- 切换门店：Home → Login → Home

## 二、SplashView（启动检查页）

### 功能说明

应用启动时检查服务器最新版本，决定是否更新或进入主流程。

### 状态流转

| 状态 | 触发条件 | UI 展示 | 可操作 |
| --- | --- | --- | --- |
| 检查中 | 进入 Splash | 居中应用名 + CircularProgress + "检查更新中..." | 无 |
| 有新版本 | 接口返回 version > 当前版本 | 红色 Badge + 新版本号 + 下载按钮 + "继续使用旧版本"按钮 | 下载更新 / 继续旧版本 |
| 正常 | 无新版本或"继续旧版本" | "跳转中..." | 自动跳转下一页 |
| 异常 | 接口请求失败 | 错误信息 + 重试按钮 + "继续使用旧版本"按钮 | 重试 / 继续旧版本 |

### 操作流程

1. 进入 Splash → 自动调用 `getAppUpdateInfo`
2. 请求成功：
   - 有新版本 → 用户选"下载更新"或"继续旧版本"
   - 无新版本 → 自动跳转
3. 请求失败 → 显示网络诊断报告（DNS/TCP/HTTP 三层）+ 重试 / 继续

### 强制更新

`forceUpdate === "1"` 时必须更新，不能选择"继续旧版本"。

## 三、LoginView（门店登录页）

### 功能说明

输入门店号进入主页。门店号持久化存储，下次启动自动跳过登录。

### 操作流程

1. 居中白色卡片容器，标题"请输入门店号"
2. 输入框（背景 #F5F5F5，回车确认）
3. 点击"输入完成"按钮或回车 → 校验非空
4. 写入 electron-store → 跳转 Home

### 校验规则

- 门店号非空（业务铁律：所有订单接口必须传门店号）
- 去除首尾空格

## 四、HomeView（主页）

### 4.1 页面结构

```
┌─────────────────────────────────────────────────┐
│ AppHeader（当前门店/切换门店 · 当前版本/新版本）   │
├─────────────────────────────────────────────────┤
│ HomeHeader（四张 ToolCard 水平排列）              │
│ ┌选择打印设备┐ ┌选择平台┐ ┌连接信息┐ ┌设置┐      │
│ └──────────┘ └───────┘ └───────┘ └────┘        │
├─────────────────────────────────────────────────┤
│ PlatformGrid（平台订单网格，每列 300px）          │
│ ┌美团─────┐ ┌京东─────┐ ┌...                    │
│ │待打印 N │ │待打印 N │                         │
│ │已打印 N │ │已打印 N │                         │
│ └────────┘ └────────┘                          │
├─────────────────────────────────────────────────┤
│ AppFooter（网络连通性状态）                        │
└─────────────────────────────────────────────────┘
```

### 4.2 加载流程

进入 Home 时执行：

1. `loadPrinted(shopId)` — 从本地数据加载已打印订单到主进程内存 `printedMap`
2. `requeuePending(shopId)` — 从本地数据恢复待打印订单入打印队列
3. `getPlatformList()` — 拉取平台列表
4. `listPrinters()` — 枚举打印设备
5. `loadSnapshots()` — 拉取打印快照（已打印/待打印 Map）刷新视图

> ⚠️ 关键：若 preload 未注入 `window.electronAPI`，上述调用全走 fallback（静默返回空值），导致接口不执行、已打印视图空。修复见 CHANGELOG 1.0.15。

### 4.3 选择打印设备（ToolCard 1）

- 枚举系统驱动打印机 + 串口设备
- 单选切换当前打印设备（Checkbox）
- 刷新按钮重新枚举
- 选中设备通过 `setPrintDevice` 持久化

### 4.4 选择平台（ToolCard 2）

- 平台列表来自 `getPlatformList`
- 多选勾选需监听的平台
- 全选 Checkbox 一键全选/全不选
- 确认后调 `updatePlatforms(platformIds, shopId)`：停止旧轮询 + 启动新平台轮询

### 4.5 连接信息（ToolCard 3）

- 实时操作日志列表（时间 + 消息）
- 追踪接口调用、打印事件、设备连接等

### 4.6 设置（ToolCard 4）

- 打印测试按钮（输出测试小票）
- 打开队列按钮（查看打印队列）

### 4.7 PlatformGrid 订单网格

每个平台一张卡片，标题含"待打印 N / 已打印 N"计数。

**待打印区**（橙色背景 #FFF3E0 标签）：
- 显示取餐号 + "待打印"状态
- 打印成功后自动移到已打印区

**已打印区**（绿色背景 #E8F5E9 标签）：
- 显示取餐号
- **重打按钮** → 调 `reprintOrder(platformId, shopId, orderId)` 重新打印
- **复单按钮** → 复制订单号到剪贴板（`clipboardWriteText`）

### 4.8 切换门店

点击 AppHeader"切换门店"图标：

1. `stopAllPolling()` — 停止所有平台轮询
2. `switchShop()` — 清空运行时状态（queue/printingSet/printedMap/pendingMap）+ 广播快照刷新
3. 跳转 LoginView，输入新门店号
4. 重新进入 Home，按新门店加载已打印/待打印数据

## 五、打印流程

### 5.1 自动轮询打印

```
每 10 秒（每个选中平台）
  → getDaySeq(wmid, shopid) 拿订单号列表
  → 过滤掉已打印（printedMap）+ 打印中（printingSet）→ 去重
  → getOrderList(wmid, shopid, 新订单号[]) 拿详情
  → 入待打印队列 → 逐个 ESC/POS 打印
  → 打印成功：写本地数据 + 移入 printedMap + 广播快照
  → 打印失败：重试（最多 3 次）→ 仍失败留在 pending 表
```

### 5.2 退款提示

- `getDaySeq` 响应含 `refundNotice` 列表
- 检测到退款通知 → 播放提示音（`noticeWavDataUrl`，6 秒冷却防频繁）

### 5.3 重启恢复

- 应用重启后 `requeuePending(shopId)` 从本地数据恢复待打印订单入队列
- `loadPrinted(shopId)` 从本地数据恢复已打印订单到内存（防重复打印）

## 六、网络检查（AppFooter）

- 定时 HEAD 请求检查服务器连通性
- Footer 实时展示：正常（绿）/异常（红）+ 最后检查时间
- 接口调用结果通过 `api:log` 事件实时反馈到 Footer

## 七、崩溃日志

- 未捕获异常 → electron-log 写文件 + 弹窗提示
- crashReporter 记录崩溃 dump
- 菜单"错误日志"可打开日志目录
- 日志路径：`%APPDATA%/pgprint-electron/logs/`

## 九、维护说明

- 新增页面：在 `src/renderer/views/` 新建组件 + `router/index.tsx` 注册路由
- 新增 IPC 通道：`preload/index.ts` 暴露 + `ipc/*.ipc.ts` 注册 handler + `bridge.ts` 封装 + `stores/` 调用
- 状态管理：Zustand store 在 `src/renderer/stores/`，每个 store 职责单一
- 代码规范：完整中文注释（文件头/函数/关键行内）、分层架构、接口参数验证
