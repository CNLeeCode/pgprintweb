# 接口对接文档

> PG到家小票打印系统 Electron 版 —— 后端接口对接说明。本文档供新同事快速了解前后端交互约定。

## 一、接口基础信息

| 项目 | 值 |
| --- | --- |
| 域名 | 由环境变量 `VITE_DOMAIN_URL` 配置，见 `src/main/config.ts`（**敏感配置，不对外公开**） |
| 接口前缀 | 见 `src/main/config.ts` 的 `API_PREFIX`（**敏感配置，不对外公开**） |
| 鉴权 | `secret` 表单参数，值见 `src/main/config.ts` 的 `API_SECRET` 常量（**敏感配置，不对外公开**） |
| 请求格式 | POST 接口用 `application/x-www-form-urlencoded`（表单），数组分发同名键 |

### 统一响应结构

后端所有接口返回标准 `RequestResult` 结构：

```json
{
  "code": 200,
  "msg": "success",
  "data": { /* 业务数据，结构因接口而异 */ }
}
```

- `code === 200` 视为成功
- `data` 为业务数据主体
- `getDaySeq` 额外在顶层带 `refundNotice`（退款通知列表）

### 字段名映射

后端字段名多为 snake_case 或自定义名，前端属性名为 camelCase。`ApiService.ts` 内置响应拦截器自动转换，关键映射见 `FIELD_MAP`：

| 后端字段 | 前端属性 | 说明 |
| --- | --- | --- |
| `orderid` | `orderId` | 订单号 |
| `day_seq` | `daySeq` | 流水号 |
| `wmid` | `platform` | 平台 id |
| `wmname` | `platformName` | 平台名称 |
| `count`（订单顶层） | `totalNum` | 订单总数 |
| `total` | `totalFee` | 订单总金额 |
| `detail` | `goodsList` | 商品列表 |
| `refund_notice` | `refundNotice` | 退款通知 |

> 注意：商品列表 `detail` 内的 `count`/`price` 是商品数量和单价，已配置豁免（`FIELD_KEEP_BY_PARENT`），不会被误转。

## 二、接口清单

### 1. getAppUpdateInfo（获取最新版本信息）

启动时由 Splash 页调用，检查是否有新版本。

| 项目 | 值 |
| --- | --- |
| 方法 | GET |
| 地址 | 由 `UPDATE_CHECK_URL` 配置（环境变量 `VITE_UPDATE_SERVER_URL`） |
| 鉴权 | 无 |

**响应数据** `AppUpdateInfo`：

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "name": "PG-PRINTER",
    "version": "1.0",
    "key": "kZasd99989Cskjk=9/a0Dsa3jlkjlkS",
    "download_url": "",
    "update_msg": "1.优化已知问题",
    "force_update": "0"
  }
}
```

**判定规则**（由 UpdateService 实现）：
- `code === 200` 且 `downloadUrl` 非空 → 有新版本
- `forceUpdate === "1"` → 强制更新（不可跳过）

### 2. getPlatformList（获取平台列表）

获取可监听的外卖平台列表。

| 项目 | 值 |
| --- | --- |
| 方法 | GET |
| 地址 | `getPlatformList` |
| 鉴权 | 无 |

**响应数据** `PrintPlatform[]`：

```json
{
  "code": 200,
  "msg": "success",
  "data": [
    { "id": "1", "name": "美团", "icon": "..." },
    { "id": "2", "name": "京东", "icon": "..." }
  ]
}
```

### 3. getDaySeq（获取订单号列表）

按平台+门店获取当日订单号列表。每 10 秒轮询一次。

| 项目 | 值 |
| --- | --- |
| 方法 | POST |
| 地址 | `getDaySeq` |
| Content-Type | `application/x-www-form-urlencoded` |

**请求参数**：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `wmid` | string | 是 | 平台 id |
| `shopid` | string | 是 | 门店号（业务铁律：非空，否则拒绝请求） |
| `secret` | string | 是 | 鉴权密钥（见 `config.ts` 的 `API_SECRET`，**不对外公开**） |

**响应数据** `DaySeqResult`：

```json
{
  "code": 200,
  "msg": "success",
  "data": [
    { "orderid": "123456", "day_seq": "001" }
  ],
  "refund_notice": []
}
```

### 4. getOrderList（获取订单详情列表）

批量获取订单详情。

| 项目 | 值 |
| --- | --- |
| 方法 | POST |
| 地址 | `getOrderList` |
| Content-Type | `application/x-www-form-urlencoded` |

**请求参数**：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `wmid` | string | 是 | 平台 id |
| `shopid` | string | 是 | 门店号 |
| `secret` | string | 是 | 鉴权密钥 |
| `orderid_list[]` | string[] | 是 | 订单号数组（表单同名多键分发） |

**响应数据** `ShopPrintOrderDetail[]`（在 `data` 字段）。

### 5. getOrder（获取单个订单详情）

重打或查询打印时调用。

| 项目 | 值 |
| --- | --- |
| 方法 | POST |
| 地址 | `getOrder` |
| Content-Type | `application/x-www-form-urlencoded` |

**请求参数**：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `wmid` | string | 是 | 平台 id |
| `shopid` | string | 是 | 门店号 |
| `secret` | string | 是 | 鉴权密钥 |
| `day_seq` | string | 是 | **订单号**（后端字段名为 `day_seq`，但实际传入的是 orderId，不是流水号，对照 KMP `DrawerContent`） |

> ⚠️ 易错点：`day_seq` 参数名易让人误以为传流水号，但实际传订单号。误传流水号会查询返回空。

**响应数据** `ShopPrintOrderDetail | null`（在 `data` 字段）。

## 三、网络诊断

`diagnoseNetwork` 是本地方法（非后端接口），分步诊断 DNS → TCP → HTTP 三层，返回多行报告：

1. DNS 解析域名，列出 IPv4/IPv6
2. TCP 连接 80 端口（3 秒超时）
3. HTTP 请求 `getPlatformList`，记录响应码

调用场景：Footer 提示网络/接口异常时供用户排查。

## 四、错误码

| code | 含义 | 处理 |
| --- | --- | --- |
| 200 | 成功 | 正常处理 |
| 非 200 | 业务失败 | 记录日志，Toast 提示 |

HTTP 层错误由 axios 捕获，`ApiService` 统一转成 `null` / `[]` 返回，并记入接口日志（`recentLogs` FIFO 50 条），通过 `api:log` 事件实时广播到渲染进程 Footer。

## 五、接口日志机制

- 每个 `ApiService` 方法在成功/失败分支都调用 `recordLog` 记一条日志
- 日志保留最近 50 条（FIFO），通过 IPC `api:getLogs` 拉取
- 实时变化通过 `api-log` 事件广播到渲染进程，Footer 状态栏实时刷新
- 主进程 electron-log 同时写文件，路径 `%APPDATA%/pgprint-electron/logs/main.log`

## 六、调用链路

```
渲染进程 (bridge.ts)
  → ipcRenderer.invoke('api:xxx')
  → IPC 层 (api.ipc.ts)
  → ApiService.xxx()
  → axios 请求后端
  → 响应拦截器 toCamelCase 字段映射
  → 返回渲染进程 (store 更新)
  → 同时 recordLog → api-log 事件 → Footer 实时刷新
```

## 七、维护说明

- 接口域名/密钥/超时等配置集中在 `src/main/config.ts`，修改时只需改一处
- 新增接口：在 `ApiService.ts` 添加方法 + 在 `preload/index.ts` 暴露 + `api.ipc.ts` 注册 + `bridge.ts` 封装
- 字段映射变更：修改 `ApiService.ts` 的 `FIELD_MAP`，注意同名字段跨类冲突时配置 `FIELD_KEEP_BY_PARENT`
